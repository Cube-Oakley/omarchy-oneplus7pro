# Charging diagnosis and bounded trial — 2026-09-17

## Verified result and current state

**The handset can charge from the current USB connection.** A monitored
one-minute trial at a 500 mA charge-current limit and 4.20 V ceiling produced
about +470 mA of measured battery current. Available charge rose from 3130
to 3138 mAh, with battery temperature around 26.1–26.2°C. USB SSH stayed up.
The power_supply driver and portable battery helper both reported Charging.

The test ended automatically after about 61.4 seconds. Original PMIC settings
were read back and verified, and the trial module was unloaded. **Charging
is disabled again, as before the experiment.** Current is back to zero with
USB attached. This is a successful bounded test, not persistent/unattended
charging support. Prioritize completing that support before suspend work.

## Why charging was disabled

`charger_snapshot.c` uses the already-probed SPMI controller to read a fixed
allowlist of PM8150b registers on USID 2. It creates an unregistered SPMI
target, performs no writes or driver probes, then releases references.
Build with `scripts/build_charger_snapshot.sh`.

Initial snapshot:

| Address | Value | Meaning from vendor SMB5 definitions |
| --- | --- | --- |
| 0x1006 | 0x47 | charger-state bits 2:0 = 7, disabled |
| 0x1042 | 0x00 | charging enable clear |
| 0x1043 | 0x00 | pause command clear |
| 0x1061 | 0x0a | 500 mA fast-charge limit (50 mA/step) |
| 0x1070 | 0x4d | 4.37 V float setting (3.60 V + 10 mV/step) |
| 0x110b | 0x95 | USB input selected and input power valid |
| 0x100d | 0x00 | no reported battery thermal-limit flags |
| 0x1651 | 0x00 | documented watchdog enable bits clear |

This explains the zero battery current after USB reconnect: the input power
path was active while battery charging was disabled. It does not establish
that every USB source or future reconnect will behave identically.

## Do not enable the existing qcom_smbx driver unchanged

The prepared native kernel has `drivers/power/supply/qcom_smbx.c`, with an
SMB5/PM8150b match, but it reuses some SMB2 encodings. Compare against the
local vendor `drivers/power/supply/qcom/qpnp-smb5.c` PM8150b parameter table
and `smb5-reg.h` under `.work/lineage-kernel/src/`:

- PM8150b FCC and USB input current use **50 mA** steps, while the available
  driver's shared `CURRENT_SCALE_FACTOR` is **25 mA**. Its 1.95 A FCC write
  would encode 3.90 A on PM8150b.
- PM8150b float voltage uses **3.60 V + code × 10 mV**. The driver's probe
  uses the SMB2 3.4875 V/7.5 mV formula. A requested 4.20 V would encode
  4.56 V on PM8150b. The vendor guacamole battery profile is 4.37 V maximum.
- Charger-state enumeration differs between SMB2 and SMB5, notably values
  0, 2 and 6. Audit status reporting per generation.
- The existing SMB5 initialization changes USB-C roles/VCONN and enables
  charging before later battery-info/IRQ setup can fail. Its final FCC write
  also ignores the battery-info limit. Thermal policy is unfinished.

These issues were found before enabling that driver; none of its initialization
writes were applied. Correct the per-generation encodings, enforce profile
limits, configure before enabling, preserve the working USB path, and define
failure/removal/thermal behavior before making it persistent. First integration
should retain conservative 500 mA / 4.20 V limits rather than fast charging.

## The bounded diagnostic

`devices/oneplus7pro/kernel/power/charger_trial.c`, built using
`scripts/build_charger_trial.sh`, requires the known guacamole/PM8150b identity,
the registered bq27541 power_supply, original disabled charge command, the
observed float value, and the existing 500 mA current limit. It also requires
valid USB input, acceptable battery voltage/temperature, and no reported
thermal/overvoltage condition.

It changes only the float ceiling (4.20 V, read back) and charge-enable bit
(read back). Every two seconds it samples battery temperature, voltage,
current, PMIC input/thermal/fault state and configured limits. Unexpected
read failure, USB loss or limit violation ends the test. The timer ends it
after roughly one minute. Cleanup first confirms charging is disabled, then
restores the original float value. It does not change USB-C, the input limit,
the fuel-gauge profile or thermal settings. This is a development diagnostic,
not a replacement for a charger driver's full protection/lifecycle handling.

Observed during trial: +431 to +471 mA in saved mid-trial samples,
voltage rose to 4.111 V, no thermal-limit flags. The `fault` log field is the
entire charger status-2 byte; its change from 0x08 to 0x28 is not itself a
reported battery-overvoltage condition (bit 1 remained clear).

After automatic stop, a separate read-only snapshot matched all initial
allowlisted register values, including charge-enable 0x00, FCC 0x0a and
float 0x4d. Battery current returned to zero.

Evidence in `out/power-investigation-20260917/`:
`charger-snapshot.log`, `charger-trial-start.log`, `charger-trial-active.log`,
`charger-trial-restored.log`. Artifacts in `out/charger-snapshot/` and
`out/charger-trial/`. No boot image was changed or firmware flashed.

## Native3 integration image prepared (not yet flashed)

The isolated `.work/linux-sm8150-codex-power` tree builds using
`scripts/build_power_desktop.sh`. The delta from native2 is saved in
`devices/oneplus7pro/kernel/power/native3-charger.patch`; the guarded SMB5
implementation is `qcom_smbx_mobile.h` alongside it. This is a guacamole
bring-up implementation, not a general upstream SMB5 replacement: it requires
the experimental `qcom,external-fuel-gauge` DT reference.

The new path disables charging before resolving dependencies; sets and reads
back 500 mA FCC, 4.20 V float, and 500 mA USB input limits; then monitors the
external gauge and PMIC every two seconds. Gauge presence, temperature,
voltage/current, USB input, thermal/overvoltage status and programmed limits
must pass before enabling. Read failures stop charging; unexpected limits,
overvoltage/overcurrent, or command/write failures latch it off until reprobe
or reboot. Temperature stop boundaries are 10/40 C, with restart restricted to
12–38 C. Voltage at or above 4.22 V stops charging; 4.25 V latches a fault.
The worker does not repeatedly send enable commands to an active cycle.
Cleanup, shutdown and suspend stop the worker and disable charging, retaining
the conservative limits. Resume resamples before enabling. Full system suspend
is still untested. The public charger properties are read-only.

The shared helper also fixes the overvoltage check (read STATUS_2, test the
returned value), SMB5 status interpretation and 50 mA current scaling. The
old SMB5 startup sequence, including its Type-C writes, is bypassed entirely.
Existing firmware USB-C/thermal configuration is retained. Hardware watchdog
configuration remains unchanged (disabled in the observed firmware state),
so software monitoring does not cover a hung kernel. This remains a supervised
development test; sustained charging, termination/taper, wall-charger operation,
and hardware protection independence have not yet been validated.

The initramfs waits for the native desktop before loading one combined overlay
that activates the tested power key, external gauge bus, and guarded charger.
The previous boot's desktop marker is cleared before starting either task.
The USB gadget advertises 500 mA in this image, matching its input ceiling.
The base DTB and filtered bootloader DTBO remain identical to native2.

Validation: host tests compile and execute the actual monitoring/cleanup C
against gauge/I/O failures, USB loss, temperature hysteresis, overvoltage,
overcurrent, incorrect encodings, unexpected command state and cleanup.
Kernel build completed without compiler warnings. Packaging checks verify the
embedded DTB/initramfs, driver configuration, external gauge phandle, battery
limits, module versions, delayed startup and preserved CPU/USB trees. The
native2 rollback manifest passes all checks.

the prepared helper. Both boot_b and dtbo_b writes succeeded; slot A was not
changed. USB SSH became available automatically. At about 142 seconds uptime,
the desktop completion marker triggered power setup; the external gauge,
PM8150 power key and guarded charger registered without manual intervention.

charge increasing from 3141 to 3144 mAh. The lower current than the earlier
trial is consistent with this build's 500 mA total USB input ceiling.

float 0x3c (4.20 V), USB input limit 0x0a (500 mA), thermal flags 0x00 and

disabled hardware state 7 while retaining all three conservative limits.

after unbind still reflected its preceding current measurement; the direct
PMIC readback is the evidence for immediate disable.

Hyprland reports native DSI 1440x3120@60, no configuration errors, the
touchscreen, power key and virtual keyboard. All eight CPUs are online and
