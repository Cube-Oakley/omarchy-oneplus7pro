# Wi-Fi bring-up — 2026-09-17

## Native4 live result: Internet and saved reconnection work

Native4 #183 was flashed to slot B with the checked helper. Boot ID
`ba65b270-4902-4306-b5b4-b533f5a6a692`. USB, native desktop, all eight CPUs,
touch/virtual keyboard and guarded charging started automatically. Runtime
reserved-memory logging confirms the 160 MiB MPSS span and both guard pages;
RMTFS exposes the original 0xf2901000 / 2 MiB usable buffer.

Manual `prepare` registered SMEM, SMP2P, QRTR and offline `remoteproc0` named
`modem`. The helper was corrected to identify MPSS by device modalias rather
than expecting its address in the human-readable name. Automatic remoteproc
recovery is disabled during this diagnostic to prevent crash/restart loops.

Read-only RMTFS and TFTP startup brought MPSS to `running` in under a second.
QRTR exposes service 69 (ATH10k WLAN firmware), along with modem services.
TFTP served the device firmware. Missing optional readwrite `ota_firewall/ruleset`
and `mcfg.tmp` requests did not prevent startup. Their absence is retained in
the logs; factory persist has not been modified.

WCN3990 initializes as chip_id 0x30224, board_id 0xff; firmware identity
`WLAN.HL.3.0.c8-00232-QCAHLSWMTPLZ-1.513311.2.516802.1`. `wlan0` appeared, and
an active scan returned 40 BSS entries across 2.4 and 5 GHz. Firmware currently
provides an invalid MAC, so ath10k chooses a random one. Repeated scans emit
`chan info: invalid frequency 0 (idx 41 out of bounds)`; scanning still succeeds,
but this firmware/driver event mismatch remains to investigate. No remoteproc
crash or SMMU fault was observed through connection-manager setup.

The first package download hit stale repository filenames. Metadata was
refreshed and NetworkManager 1.58.1, wpa_supplicant 2.12 and wireless-regdb were
installed with their new dependencies; the existing graphics stack was not
upgraded. Package hooks regenerated the unrelated generic `/boot` initramfs;
the flashed native4 image was not changed. `iw reg reload` loads the signed
regulatory database after its initial absence. No country was guessed.

NetworkManager runs using `NetworkManager-test.conf`, leaving usb0 explicitly
unmanaged. A system D-Bus instance and machine ID were initialized for the
chroot session. The initial `nmcli --ask` prompt expired before the user could
finish. Its replacement (`overlay/mobile/wifi-connect.py`) waits indefinitely
for hidden terminal input before invoking NM with a mode-0600 volatile password
file; the file is removed after activation. Saved-profile secrets stay on the
phone and out of collected evidence.

test-network authenticated on 5260 MHz with an 80 MHz VHT link and DHCP address
192.0.2.42. HTTPS succeeded with curl explicitly bound to wlan0. The old
metric-zero USB default was replaced with metric 2000; Wi-Fi's metric 600 now
wins, while the directly connected USB SSH subnet remains available. Unbound
HTTPS then reported the Wi-Fi source address. A down/up reconnect passed, and
after terminating/restarting NetworkManager the saved profile autoconnected
without another prompt. `pacman -Sy` using a temporary database successfully
downloaded core/extra/alarm/aur metadata over the Wi-Fi route. No full package
upgrade was performed. Modem remained running, no crash/SMMU fault appeared,
and charging continued at 79%, 27 C during the final check.

### Automatic radio startup verified after full reboot

`scripts/phone-radio-start.sh` is installed as
`/usr/local/sbin/guacamole-radio-start`. It is gated by native4 and
`/root/radio-bringup/autostart-enabled`, waits for the power driver, verifies
module hashes, loads radio control, starts read-only RMTFS/TFTP, checks/starts
MPSS, loads Wi-Fi, adjusts USB routing and starts D-Bus/NetworkManager. A lock
whose descriptor is not inherited by daemons prevents simultaneous startup;
an attempted marker prevents repeating a failed radio boot in the same boot.
Remoteproc automatic crash recovery stays disabled.

The device's `desktop-prepare.sh` launches it asynchronously because native4's
early USB helper is frozen inside the flashed image. The updated persistent
USB bootstrap helper also starts it when explicitly invoked; future image
builds include that helper. Live startup and a repeat invocation passed.
The subsequent physical fastboot cycle and `fastboot reboot` (no flash) booted
native4 #183 with new boot ID `88339e83-efd3-4e74-a8e8-30b15725e74e`.
USB SSH was available at 14 seconds. The delayed display/touch sequence reached
desktop readiness around 141 seconds; charging enabled at 141.96, MPSS ran at
145.56, and Wi-Fi associated with test-network at 160.82 seconds. No manual bootstrap,
module insertion or connection command was used. `/run/guacamole-radio.ready`
was present. All eight CPUs, native DSI 1440x3120@60 scale 3, Quickshell, one
hidden wvkbd process and an empty Hyprland config-error report were verified.
Wi-Fi obtained 192.0.2.42 (its random MAC changed across boot), and the Wi-Fi
default route again took priority over USB. Charging continued around 27.4 C,
79%; one sample during package traffic showed discharge under load, then the
final sample showed +268 mA charging. No radio crash/SMMU fault was observed.

To disable radio autostart, remove the
`autostart-enabled` file; that affects subsequent startup, not the live modem.
After a failure, inspect `logs/startup.log` before clearing
`/run/guacamole-radio.attempted` to retry. Do not kill RMTFS under a running modem.

### Network time fixes HTTPS after the clock reset

The fresh boot left the clock in January 1970. test-network associated normally, but
curl rejected the HTTPS certificate as not yet valid. No certificate checks
were disabled and no host clock adjustment was used in this boot.

The already installed systemd-timesyncd 261.2 daemon works independently of the
systemd service manager when supplied its service directories, system D-Bus,
service UID and CAP_SYS_TIME. `scripts/phone-time-sync.sh`, installed as
`/usr/local/sbin/guacamole-time-sync`, provides this chroot adapter. It uses
the distribution's NTP defaults, the `systemd-timesync` account, only SYS_TIME
in effective/bounding/ambient capabilities, and no-new-privileges. It saves a
clock floor in `/var/lib/systemd/timesync/clock`; the standard behavior is
documented in the installed man page and [upstream source](https://github.com/systemd/systemd/blob/main/src/timesync/timesyncd.c).

Live start advanced the 1970 clock to the packaged epoch, contacted an Arch NTP
pool server, and synchronized to current UTC in about a second. The runtime
sync marker and persisted timestamp were verified. HTTPS with normal certificate
validation, explicitly bound to wlan0, returned 200; pacman synced all configured
repository databases to a temporary directory. `phone-radio-network.sh` now
launches the optional time service when NetworkManager becomes ready; a repeat
invocation passed without duplicating it. **That new time-sync hook has not yet
been observed through another full reboot.** No package installation was needed.

## Evidence and board-specific choices

The related [hotdog bring-up](https://github.com/Sr-0w/hotdog-linux-bringup/blob/main/docs/evidence/2026-08-04-mainline616-wifi-mpss.md)
establishes MPSS/RMTFS before WCN3990. Its RMTFS address is **not** used here:
guacamole's existing `0xf2901000`, 2 MiB reservation already binds successfully.
Two 4 KiB no-map guard pages are added at boot, before radio firmware starts.
The downstream guacamole `18821/sm8150.dtsi` enables guard memory for RMTFS.

The modem firmware extracted from this project's guacamole Lineage payload
loads at 0x8dc00000 and spans 160 MiB. The inherited mainline DT reserves only
150 MiB. Vendor `18821/sm8150-oem.dtsi` explicitly overrides the modem size to
160 MiB; every load segment now fits native4's reservation.

To isolate this experiment, the old video and SLPI reservations are disabled,
and the unused tail 0x97c00000–0x98b00000 remains reserved/no-map. Those
processors remain disabled. The union of reserved RAM is unchanged apart from
the two RMTFS guard pages; there are no overlapping enabled reservations.
GPU, IPA, WLAN and RMTFS addresses are unchanged. Before enabling video, SLPI,
CDSP or IPA, reconcile the **complete** modern OEM map; their legacy locations
must not be treated as compatible with this newer firmware. This is an
intentional staged map, not final platform support.

Wi-Fi's four explicit regulator supplies follow guacamole's vendor CNSS node:
L1A, L7A, L2C and L11C. Hotdog's extra L10C vote is omitted: guacamole's vendor
tree uses L10C for audio and does not list it for CNSS. An omitted optional
supply may produce a dummy-regulator message; investigate actual results
before assigning an unverified rail.

## Prepared artifacts and tools

- Isolated kernel `.work/linux-sm8150-codex-wifi`, built with
  `scripts/build_wifi_desktop.sh`; native3 tree/checkpoint is preserved.
- `guacamole-radio-guards.dts` is embedded at boot; SMEM/MPSS/Wi-Fi stay disabled.
- Manual `radio_control_overlay` enables SMEM and registers MPSS; the PAS
  driver's `auto_boot=false` lets the RMTFS service start it explicitly.
- A separate `wifi_overlay` enables Wi-Fi only after MPSS runs.
- `scripts/build_radio_modules.sh` builds the narrow dependency set, including
  RFKill, CFG80211, MAC80211, ARC4, QRTR/GLINK, Q6/PAS, PD mapper and ath10k.
  Every reported module dependency is included, with native4 vermagic.
- Firmware is staged as files under
  `/lib/firmware/qcom/sm8150/oneplus/guacamole/`, never flashed to firmware
  partitions. MDT split-segment sizes and all installed file hashes pass.
- The source FAT image omits its unused zero tail; a working copy was padded
  to the declared 256 MiB before clean 7z extraction. Original unchanged.
- Upstream [QRTR](https://github.com/linux-msm/qrtr),
  [RMTFS](https://github.com/linux-msm/rmtfs), and
  [tqftpserv](https://github.com/linux-msm/tqftpserv) sources are pinned in
  `out/radio-sources.json`; native builds are in `/root/radio-bringup/bin/`.
  `iw` 6.17 was installed through ordinary pacman.
- `/root/radio-bringup/phone-radio-test.sh prepare|modem|wifi` is a manual
  helper, not an automatic startup service. It refuses kernels other than
  native4. Modem storage partition labels are verified before private links
  are created. RMTFS uses `-r -P -s`: storage writes go to its RAM shadow,
  preserving the physical modem/EFS partitions. tqftpserv writes only its
  ordinary Linux data directory; factory persist data is not mounted/changed.

Preflight: `scripts/verify_native_display.py native4` (with wifi tree/output
environment variables), `scripts/verify_radio_preflight.py`, shell syntax,
module closure/vermagic, firmware segment bounds and installed firmware hashes
all pass. No module unresolved-symbol errors were suppressed. Kbuild's generic
missing Module.symvers warning occurs for these external builds; explicit
vmlinux and previously built module symbol files are supplied to modpost.
